# Специфікація: каталог відеоігор та бібліотека користувача

## Намір

Описати каталог ігор за жанрами та особисті бібліотеки користувачів
із датою додавання і статусом проходження кожної гри.

## Сутності та атрибути

- USER: id — int, PK; username — string; email — string, унікальний.
- GAME: id — int, PK; title — string; description — string;
  release_date — date.
- GENRE: id — int, PK; name — string, унікальний.
- LIBRARY_ENTRY: user_id — int, PK і FK → USER.id;
  game_id — int, PK і FK → GAME.id; added_at — datetime;
  status — string.

У LIBRARY_ENTRY первинний ключ складений: (user_id, game_id).
Усі атрибути обов’язкові; текстові значення непорожні.
Каталог містить лише випущені ігри з відомою датою виходу.
Допустимі статуси: planned, playing, completed
(«Заплановано», «У процесі», «Пройдено»).

## Зв’язки та правила

R1. Користувач має від нуля до багатьох записів бібліотеки.
Кожен запис належить рівно одному користувачу.

R2. Гра має від нуля до багатьох записів бібліотеки.
Кожен запис посилається рівно на одну гру.

R3. Гра має від одного до багатьох жанрів.
Жанр може бути пов’язаний із нулем або багатьма іграми.
Це прямий неідентифікуючий зв’язок багато-до-багатьох без сполучної
сутності: GAME і GENRE ідентифікуються власними незалежними ключами.

R4. Пара (user_id, game_id) унікальна.
Статус і дата додавання належать запису бібліотеки.
LIBRARY_ENTRY є асоціативною сутністю з власними атрибутами.

## Критерії прийняття

AC1. Модель містить рівно чотири визначені сутності;
назви й типи всіх атрибутів збігаються з цією специфікацією.

AC2. Первинні та зовнішні ключі позначені.
Усі ідентифікатори й відповідні посилання мають тип int.
Складений ключ LIBRARY_ENTRY забороняє повторення пари користувач–гра.

AC3. Мінімальні й максимальні кількості у зв’язках відповідають R1–R3.
Окремої сполучної сутності між GAME і GENRE немає.
GAME–GENRE позначено пунктирною лінією (..), оскільки зв’язок
неідентифікуючий. Зв’язки з LIBRARY_ENTRY — суцільними (--),
оскільки ключі USER і GAME входять до її складеного PK.

AC4. Атрибути атомарні; дані користувача, гри та жанру
не дублюються в LIBRARY_ENTRY. Неключові атрибути залежать
від усього ключа, без транзитивних залежностей (3НФ).

AC5. Обов’язковість атрибутів, унікальність email і назви жанру,
допустимі статуси та обмеження каталогу задокументовані біля моделі.

AC6. ER-діаграма згенерована з текстового опису Mermaid
та відповідає його поточній версії.
